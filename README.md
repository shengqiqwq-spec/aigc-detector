# AI 文本检测器 & 文本改写工具

**中文** | [English](README_EN.md)

一套**完全本地运行**的 AIGC 文本检测器，附一个保守的文本改写工具。
模型矩阵从手机到桌面全覆盖，运行时只需要 numpy。

---

## ✨ 核心亮点

- **4 个模型档位**：357KB 手机版 → 2.8MB 通用版，按硬件自动选择
- **中文检测 F1 = 0.9812**（分组防泄漏独立集，误报 1.17%，长文本 F1 1.0000；`docs/能力边界说明.md` 有二分类/来源归因两个口径的诚实对比）
- **中英双语**：自动识别语言，自动切换模型
- **只要 numpy**：四个档位都带纯 numpy 推理路径，不用装 sklearn
- **纯本地运行**：无需联网、无 API 费用、数据不外传
- **零幻觉改写**：规则改写不改事实/数字、不改语域（但降 AI 概率有限，见下文）

> 📖 第一次用建议先看 **[怎么用好](docs/怎么用好.md)** —— 讲清楚了什么情况下它准、
> 什么情况下会静默失灵，以及为什么它宁可说"判不了"也不编造分数。

## 📊 模型矩阵

**分组防泄漏切分评估**（同一问题的 Q/A 不跨训练集/测试集）：

| 档位 | 模型 | 体积 | 整体 F1 | 短文本 | 中文本 | 长文本 |
|---|---|---|---|---|---|---|
| **tier1** ⭐ | TF-IDF+LR (v11) | 2.6MB | **0.9812** | 0.9521 | 0.9778 | 0.9904 |
| **en** ⭐ | TF-IDF+LR 双特征 (v10) | 5.3MB | **0.9899** | 0.9513 | 0.9939 | 0.9894 |
| tier3 | CharTextCNN | 1.9MB | **0.9709** | — | — | 极速 0.5ms |
| tier0 | Hashing+NB | 421KB | **0.9144** | — | — | 手机/嵌入式(中文) |
| en_tier0 | Hashing+NB | 357KB | **0.9408** | — | — | 手机/嵌入式(英文) |

> **v9 英文模型是一次完整性修复（2026-11-20）。** 之前的仓库里 `pred_en`
> 指向 `detector_en_v5`，而这个模型只在 1702 条 AI 文本上学过，对 HC3 式
> 英文 AI 答案**只能检出 13.3%**（AI 均分 0.105）。上表 0.9905 是训练侧
> 记录的指标，但发出去的权重并不是它 —— 文档与产物不一致。
> v9 用本地 16 核扫了 48 组特征/超参后重训（char_wb(2,5) + word 双特征），
> 在分组防泄漏独立集（11,157 条）上实测 **F1 0.9899 / 误报 0.55% / 召回 99.10%**。
> v10 又补了 126 条本机生成的英语功能性文体样本：四类文体命中 1/4 → 2/4，
> 手写 8 条全新样本 2/8 → 3/8（8 条分数全部上升），独立集 F1 持平。
>
> 代价：英语功能性文体仍是弱项 —— 商务备忘、客服话术还在阈值下
> （0.106 / 0.086）。要真正解决得补几千条这一带的语料，详见「已知局限」。

## 🎯 准确率预期

**先说清楚：准确率取决于文体，不只看长度。**

在上面测过的文体范围内（说明文、论述文、技术解析、新闻稿、说明书、
公文、邮件、纪要、指南、营销、社交）：

| 文本长度 | 准确率 | 建议 |
|---|---|---|
| 300 字以上 | 98%+ | ✅ 最可靠 |
| 150-300 字 | 97~98% | ✅ 可靠 |
| 80-150 字 | 95% 左右 | ✔ 较可靠 |
| 50-80 字 | ~93% | ⚠ 中等 |
| **50 字以下** | 仅供参考 | ⚠ 信息不足 |

**但这张表只适用于上面这些文体。** 换成这些：

| 文体 | 实测 AI 概率 | 结果 |
|---|---|---|
| 产品介绍（带型号参数） | **0.11** | ❌ 判成人类 |
| 影评（带片名导演） | **0.10** | ❌ 判成人类 |
| 旅游攻略（带地名路线） | **0.13** | ❌ 判成人类 |
| 学术摘要（带方法数据集） | **0.17** | ❌ 判成人类 |

**上面四类都是我现场手写的、明显是 AI 文风的中文，模型判为「大概率人类」。**

原因：这类文本每句话都由具体名词构成（「AMOLED」「大理白族自治州」「ResNet-50」），
而这些词在训练数据的 AI 侧从未出现。TF-IDF 判的是词频统计——
**它不认识的词等于不存在**。

所以我专门生成了 173 条这六类文体的 AI 样本重训，加权到 100 倍，
盲区识别也只从 0/6 提到 2/6。**这是线性 TF-IDF 的类别限制，不是调参问题。**

**如果贴进去的文本满是专有名词、参数、地名、片名，别信它的"低"。**

## 🔍 怎么看结果

```json
{"language": "zh", "ai_probability": 0.988, "bucket": "高", "confidence": "高(长文本~99.6%)"}
```

- `ai_probability`：0~1 的 AI 概率
- `bucket`：高(≥0.7) / 中(0.3-0.7) / 低(<0.3)
- `confidence`：根据文本长度给出的置信度提示

**不要当判决书**——这是概率，不是证据。

## 🛠 降 AI 功能

**先说结论：规则改写基本降不动 AI 概率，这是一个诚实的边界。**

| 方案 | 实测降幅 | 依赖 | 特点 |
|---|---|---|---|
| **humanize2.py** ⭐ | 中文论述 **0.975 → 0.947** | 无 | 规则改写，零依赖，保语域 |
| evasion_engine.py | 术语表内的词条 | 无 | 零幻觉，保事实/数字 |
| humanize_pro.py | 需本地大模型 | Qwen3-14B 以上 | 语义级重写，唯一真能降的 |

### 实测（各 100 条真实 AI 文本，strength 拉满）

| 文体 | 改写前 | 改写后 | 从「高」降到阈值下 |
|---|---|---|---|
| 中文论述 | 0.975 | 0.947 | **0/60** |
| 中文公文 | 0.869 | 0.782 | 5/95 |
| 中文社交 | 0.625 | 0.516 | 3/29 |
| 英文 AI | 0.974 | 0.943 | 2/75 |

### 为什么降不动

看这两个分布：

- 真人中文 300 条：AI 概率**中位 0.007**，95% 分位 0.155
- AI 论述 100 条：AI 概率**中位 0.990**，最低 0.843

中间是一条鸿沟。而这个检测器看的是 **TF-IDF 词频分布**——
200 字文本有两三百个词，改写器改 3~8 处，分布几乎不动。

**strength 从 1.0 拉到 5.0，降幅只从 0.010 到 0.028。这不是调参能解决的。**

### 一个必须记录的历史错误

早先 README 写「公文 0.80 → 0.29，71/75 过线」。那个数字是真的，
但代价是**把公文改成了病句**：

```
原文: 各部门：请高度重视，认真组织实施。
改写: 各部门：请看重，好好安排实施（我们试过）。
```

```
原文: 已经包括大量的数据集
改写: 已经里面有大量的数据集        ← 语法错误
```

「降得动」的版本是坏的版本。现在的版本优先保证改完能读，代价是降不动。
这是一个**刻意的取舍**，不是退步。

### 真要降 AI 比率

只有一条路：**LLM 语义重写**——不是换词，是重新组织句子和论述顺序。
`humanize_pro.py` 干这个，但需要本地跑大模型，每条几十秒。

```bash
# 规则改写（无需模型）
python src/humanize2.py "你的文本"

# 程序化引擎（零幻觉，保事实）
python src/evasion_engine.py "你的文本"

# LLM 改写（需先部署 llama.cpp + Qwen3-14B）
python src/humanize_pro.py "你的文本" --target 0.3
```

## 🔌 HTTP API

启动服务后有三个端点，全部 CORS 开放，可被浏览器直连。

```bash
python src/serve.py     # 默认 http://127.0.0.1:8000
```

### `POST /detect` — 检测文本

```bash
curl -X POST http://127.0.0.1:8000/detect \
  -H "Content-Type: application/json" \
  -d '{"text": "要检测的文本内容……"}'
```

返回：

```json
{
  "language": "zh",
  "tier": "tier1",
  "ai_probability": 0.7405,
  "bucket": "高",
  "confidence": "中(80-200字 F1~0.98)",
  "text_len": 107,
  "latency_ms": 1.2
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `ai_probability` | 0–1，越大越像 AI 生成 |
| `bucket` | 高(≥0.7) / 中(0.3–0.7) / 低(<0.3) |
| `confidence` | 由**文本长度**决定的可靠度，短文本会主动向 0.5 收缩 |
| `tier` | 实际使用的模型档位 |
| `error` | 出现时表示输入无法判断，见下 |

**被拒绝的输入**（此时 `ai_probability` 为 0，看 `error` 字段）：

| `error` | 触发条件 |
|---|---|
| `no_meaningful_content` | 空或纯符号/空白（HTTP 200，`error` 字段标明） |
| `empty text` | 完全没传 text（HTTP 400） |
| `not_natural_language` | JSON / HTML / 代码 / 纯数字公式 |
| `repetitive_content` | 大段重复（同一句话复制很多遍） |

这些情况下我们**不给概率**——给 JSON 打分 0.42 看着很像结论，其实毫无意义。

### `GET /info` — 机器画像

返回核数、内存、是否有 torch、推荐的档位。第一次调用会导入 psutil（约 1.4 秒），之后走缓存。

### `GET /health` — 健康检查

```json
{"status": "ok", "service": "aigc-detector"}
```

静止返回，不碰模型、不碰 psutil。容器探针/负载均衡/监控用这个，别用 `/info`。

### Python 里直接调用（不走 HTTP）

```python
import sys; sys.path.insert(0, "src")
import model_zoo as M

M.warm_up()                       # 预热，之后每次 0.04ms（tier1 实测中位）
r = M.detect("要检测的文本……")
print(r["ai_probability"], r["bucket"])

# 指定档位（默认 auto：按语言 + 机器性能自动选）
r = M.detect("text", tier="tier0")
```

## ❓ 常见问题

### 端口被占用 / 启动后打不开页面

```bash
# Windows 查谁占了 8000
netstat -ano | findstr :8000
# 结束它（把 <PID> 换成上面查到的）
taskkill /F /PID <PID>
```
换端口启动：改 `src/serve.py` 末尾的 `PORT = 8000`。

### `ModuleNotFoundError: No module named 'torch'`

只有 `tier3`（CNN 档）需要 torch。默认的 `tier1`/`en` 不需要，且准确率更高。
要么 `pip install torch`，要么直接用默认档。

### 第一次检测很慢

那是 Python 导入 sklearn 的开销（单这一项就 1.2 秒），不是模型慢。

**已优化**：模型以 `fast.npz`（纯数组格式）发布，加载时不碰 sklearn，
冷启动从 **1719 ms 降到 387 ms**（5 次实测中位）。

**仓库里只发 npz，不发 sklearn 原件。** 四个档位加起来 8MB（带 pkl 是 36MB），
clone 体积小 78%。想自己重训的用户生成 pkl 后跑 `scripts/export_fast.py`
转成 npz 即可，也可以用 `_load_joblib` 的 sklearn 回退路径。

自己写脚本时仍建议先预热一次：

```python
import model_zoo as M
M.warm_up()          # 之后每次 detect 0.04ms(tier1) / 0.10ms(en) / 0.27ms(tier0)
```

想给其他模型也生成快路径（例如自己重训的）：

```bash
# 只有自己重训过模型(model 目录里有 clf.pkl / v1.pkl)时才需要跑这个。
# 仓库里发布的 ckpt/ 已经带好了 fast.npz, 直接用就行, 不需要导出。
python scripts/export_fast.py ckpt/detector_zh_final          # 单特征 TF-IDF+LR
python scripts/export_fast.py ckpt/detector_en_v5 --dual      # 双特征 TF-IDF+LR
python scripts/export_fast.py ckpt/detector_tier0 --nb        # Hashing+NB 轻量档
```

四个档位都已覆盖。冷启动 1719 ms → **387 ms**，热路径（各 500 次实测中位）:

| 档位 | sklearn 路径 | 纯 numpy 路径 |
|---|---|---|
| tier1 | 1.20 ms | **0.044 ms** |
| en | 1.43 ms | **0.103 ms** |
| tier0 | 0.71 ms | **0.272 ms** |
| en_tier0 | 0.71 ms | **0.310 ms** |

纯 numpy 推理与 sklearn 数值一致到 **1e-8**（有测试守门）。

### 短文本判定飘忽

40 字以下信息量不足，概率会主动向 0.5（"中"档）收缩——这是**有意为之**，
避免给出虚假的确定性。要更准请测 150 字以上，或同一内容多测几段。

### 结果和 Turnitin / GPTZero 不一致

正常，也不该期望一致。本项目是独立模型，评估口径是自建金标准集上的
分组防泄漏 F1，不对齐任何商业检测器的百分比。判"高"不代表作弊，
判"低"也不代表没用 AI。

### 中文文档检测为"低"，但它确实是 AI 写的

两种可能：

1. **文本是知情者刻意规避写的**——避开所有 AI 语言习惯（不用"首先/其次/
   综上所述"、多写短句和具体细节），任何统计特征检测器都会漏判。
2. **文风不在训练覆盖范围内**——技术笔记、代码注释这类文体训得少。

### 能不能检测其他语言的文本？

目前只支持中文和英文，按 CJK 字符占比自动路由。

**其他语言会被明确拒绝**，返回 `error: "not_natural_language"`，
不会给出一个煞有介事的假分数。实测阿拉伯文、日文都会走这条路径。

（早期版本会把日文当成中文处理，因为汉字在 CJK 区间里。现在直接拒绝。）

### 模型能商用吗？

代码 **Apache 2.0**，商用无限制。

**模型权重是 CC BY-SA 4.0**——因为基于 HC3（CC BY-SA 4.0）训练，ShareAlike 条款
延伸到衍生模型。商用可以，但分发改造后的权重时要保留署名和相同许可。

不想受 ShareAlike 约束？用你自己的数据重训：
`scripts/train_zh_v7.py` / `train_en_v8.py` 是完整流程。详见[许可](#-许可)。

## ⚠️ 已知限制

1. **短文本弱于长文本**：<50 字信息不足，检测必然有歧义（信息论天花板）
2. **识别的是"模型指纹"，不是"AI 感"**：对真实模型输出极准（实测 Qwen-1.5B 100%、Qwen3-VL-30B 96%、GPT-3.5 99.6%），但对**刻意规避的文本会漏判**
3. **知情者可以绕过**：如果你了解检测器原理，刻意避开所有 AI 语言习惯（不用"首先/其次/总的来说"、多写短句和具体事实），检测器会判低。实测：AI 手写的 5 段规避式文本全部漏判（p=0.006~0.069）。这是所有基于统计特征的检测器的共同边界，不是本项目的缺陷
4. **换新模型需重训**：AI 模型持续进化，检测器需重新生成数据训练
5. **不等同 Turnitin**：独立指标，无法对齐任何商业检测器的精确百分比
6. **纯符号/空白输入会被拒绝**：返回 `error: no_meaningful_content` 而非猜测概率

## 🤝 技术说明

### 为什么用 TF-IDF 而不是 Transformer？

在 CPU 上实测：roberta-base 单步训练 33 秒（80 步需 44 分钟），完全不可行。
改用字符级 TF-IDF + 逻辑回归：**68 秒训完，F1 反而更高**。

### 为什么混入 Qwen 生成的数据？

HC3 数据集是 2022 年 GPT-3.5 风格，对当代模型输出识别率极低（英文仅 0.05）。
用本地 Qwen 生成 1,860 条当代中文 + 888 条英文 AI 文本混合训练后：
- 中文当代 AI 检测率：96.7%
- 英文从 0.05 修复到 **0.9905**
