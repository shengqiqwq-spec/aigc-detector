# AI Text Detector & Humanizer

[中文](README.md) | **English**

A **fully-local** toolkit for AIGC (AI-generated content) text detection and humanization, with a model matrix scaling from phones to desktops.

---

## ✨ Highlights

- **4 model tiers**: 357KB (mobile) → 2.8MB (universal), auto-selected by hardware
- **Chinese detection F1 = 0.9814** (leak-free grouped split; 98.96% on long text)
- **Bilingual**: auto-detects language and switches models automatically
- **numpy only**: every tier ships a pure-numpy inference path, no sklearn needed
- **100% local**: no network, no API cost, no data upload
- **Zero-hallucination humanizer**: programmatic n-gram audit, never alters facts/numbers

> 📖 Read **[怎么用好](docs/怎么用好.md)** first (Chinese) - it explains when the
> detector is reliable, when it silently fails, and why it returns "cannot judge"
> instead of inventing a score.

## 🚀 Quick Start

```bash
# 1. Install dependencies (numpy is enough - every tier ships a pure-numpy fast path)
pip install -r requirements.txt

# 2. Detect text (auto language detection + auto tier selection)
python src/model_zoo.py "your text here"

# 3. Check recommended tier for your machine
python src/model_zoo.py --info
```

## 🔍 Reading the Output

```json
{"language": "en", "ai_probability": 0.943, "bucket": "高", "confidence": "高(长文本~99.6%)"}
```

- `ai_probability`: AI probability from 0 to 1
- `bucket`: High (≥0.7) / Medium (0.3-0.7) / Low (<0.3)
- `confidence`: confidence hint based on text length

**Not a verdict** — this is a probability, not evidence.

| Method | Reduction | Dependency | Notes |
|---|---|---|---|

| humanize_pro.py | needs a local 14B model | Qwen3-14B | Semantic rewrite, best quality |
| evasion_engine.py | 96% (in-vocab) | None | Zero hallucination, preserves facts |

```bash
# Rule-based rewrite (no model needed)
### What the rule-based humanizer can and cannot do

Measured by rewriting one passage 75 times (strength 1.0/2.0/3.0, 25 each)
and recording the detector score.

| Input | original | best | below 0.5 |
|---|---|---|---|
| Chinese officialese | 0.804 | **0.161** | **71/75** |
| English academic (slogan-dense) | 0.966 | **0.130** | **75/75** |
| Chinese explanatory (AI keyphrases) | 0.918 | 0.532 | **0/75** |

Reference: real human text scores a median of **0.053**, 75th percentile
**0.066**, max **0.196** on this detector.

> ⚠️ **The limit you need to know**: rule-based rewriting pushes the score
> below the threshold but **never down to where real human writing sits**.
> Chinese explanatory text dominated by AI keyphrases still only reaches
> 0.51 even after every phrase is swapped for plain speech - and by then the
> meaning has collapsed ("按人教的系统能够按人教"). The rule-based humanizer
> rewrites word forms; it cannot touch the syntactic and content-level
> signatures of AI output. For text that genuinely reads as human, use the
> LLM rewriter (`humanize_pro.py`), not rule substitution.

```bash
python src/humanize2.py "your text"

# Programmatic engine (zero hallucination)
python src/evasion_engine.py "your text"

# LLM rewrite (requires local llama.cpp + Qwen3-14B)
python src/humanize_pro.py "your text" --target 0.3
```

## 🔌 HTTP API

Three endpoints, all CORS-open, safe to call straight from a browser.

```bash
python src/serve.py     # default http://127.0.0.1:8000
```

### `POST /detect`

```bash
curl -X POST http://127.0.0.1:8000/detect \
  -H "Content-Type: application/json" \
  -d '{"text": "the text to score"}'
```

```json
{
  "language": "en",
  "tier": "en",
  "ai_probability": 0.7405,
  "bucket": "high",
  "confidence": "medium (80-200 chars, F1~0.98)",
  "text_len": 107,
  "latency_ms": 1.2
}
```

| field | meaning |
|---|---|
| `ai_probability` | 0-1, higher = more AI-like |
| `bucket` | high (>=0.7) / medium (0.3-0.7) / low (<0.3) |
| `confidence` | reliability implied by **length**; short text is pulled toward 0.5 on purpose |
| `tier` | which model actually ran |
| `error` | present when the input cannot be judged, see below |

**Rejected inputs** (`ai_probability` is 0; read `error`):

| `error` | trigger |
|---|---|
| `no_meaningful_content` | empty, or only punctuation/whitespace (HTTP 200, flagged in `error`) |
| `empty text` | no `text` key at all (HTTP 400) |
| `not_natural_language` | JSON / HTML / code / bare numbers or formulae |
| `repetitive_content` | long spans repeated (the same sentence pasted many times) |

No score is returned for these on purpose - reporting 0.42 for a JSON
fragment looks like a finding but means nothing.

### `GET /info`

Cores, RAM, torch presence, recommended tier. First call imports psutil
(~1.4 s), cached after that.

### `GET /health`

```json
{"status": "ok", "service": "aigc-detector"}
```

Static, touches neither the model nor psutil. Use this for container
probes, load balancers and monitoring - not `/info`.

### Calling it from Python

```python
import sys; sys.path.insert(0, "src")
import model_zoo as M

M.warm_up()                       # then each detect() is ~0.02 ms
r = M.detect("the text to score")
print(r["ai_probability"], r["bucket"])

r = M.detect("text", tier="tier0")   # force a tier; default is auto
```

## ❓ FAQ

### Port already in use / page won't open

```bash
# Windows: find who holds 8000
netstat -ano | findstr :8000
taskkill /F /PID <PID>
```
To use another port, change `PORT = 8000` at the end of `src/serve.py`.

### `ModuleNotFoundError: No module named 'torch'`

Only `tier3` (the CNN tier) needs torch. The default `tier1` / `en` do not,
and they are more accurate. Either `pip install torch`, or just use the default.

### The first detection is slow

That is Python importing sklearn (1.2 s of it on its own), not the model.

**Now optimized**: each model ships as `fast.npz` (plain arrays) and loads
without touching sklearn, cutting cold start from **1719 ms to 575 ms**.

**The repo ships npz only, not the sklearn originals.** All four tiers total
8 MB instead of 36 MB - a 78% smaller clone. If you retrain a model and
produce `.pkl` files, run `scripts/export_fast.py` to convert them; the
sklearn fallback path is still there for anyone who wants it.

Pre-warming is still worth it in your own scripts:

```python
import model_zoo as M
M.warm_up()          # afterwards each detect() takes 1-2 ms
```

To generate the fast path for a model you trained yourself:

```bash
python scripts/export_fast.py ckpt/detector_zh_final          # single TF-IDF+LR
python scripts/export_fast.py ckpt/detector_en_v5 --dual      # dual TF-IDF+LR
python scripts/export_fast.py ckpt/detector_tier0 --nb        # Hashing+NB tier
```

All four tiers are covered. Cold start 1719 ms -> 581 ms; hot path:

| Tier | before | after |
|---|---|---|
| tier1 | 1.20 ms | **0.02 ms** |
| en | 1.43 ms | **<0.01 ms** |
| tier0 | 0.71 ms | **0.11 ms** |
| en_tier0 | 0.71 ms | **0.08 ms** |

The numpy inference matches sklearn to **1e-8**, which a test enforces.

### Short text gives jumpy results

Under 40 characters there is not enough signal, so the probability is
deliberately shrunk toward 0.5 ("Medium") rather than reported with false
confidence. Use 150+ characters, or test several passages.

### Results disagree with Turnitin / GPTZero

Expected. This is an independent model evaluated by grouped-split F1 on its
own gold set - it does not attempt to reproduce any commercial detector's
percentage. "High" is not an accusation and "Low" is not a clearance.

### A Chinese document that is definitely AI-written scores Low

Two likely causes:

1. **It was written by someone who knows the detector** and avoided every AI
   language habit. Any statistical detector misses this.
2. **Unusual register** - technical notes and code comments are thin in the
   training data.

### Other languages?

Chinese and English only, auto-routed by CJK character ratio. Other languages
fall through to the Chinese model and the result is not meaningful.

### Commercial use?

Code is Apache 2.0. Training used [HC3](https://huggingface.co/datasets/Hello-SimpleAI/HC3)
(CC BY-SA 4.0) - check that dataset's terms before commercial use.

## 🔬 External Validation (held-out data)

Measured on data the model **never saw during training**:

| Test set | N | Result |
|---|---|---|
| Chinese human text | 2500 | **0.52% false positive** (13/2500) |
| Chinese GPT-3.5 | 500 | **99.6% flagged** (mean 0.967) |
| Chinese Qwen-1.5B (modern) | 80 | **100% flagged** (mean 0.969) |
| Chinese Qwen3-VL-30B (cross-model) | 23 | **95.7% flagged** (mean 0.867) |
| English human text | 2500 | **0.56% false positive** (14/2500; down from 9.1% before v8) |
| English GPT-3.5 | 294 | **100% flagged** (mean 0.986) |
| English Qwen-1.5B (modern) | 56 | **100% flagged** (mean 0.953) |

Recall is not uniform across registers when measured on a larger, unfiltered
sample. Chinese AI text, 720 passages from six sources: **94.2%**. Broken down:

| Source | Recall |
|---|---|
| Modern essays | 100% (200/200) |
| Short text | 100% (134/134) |
| Mixed registers (memo/email/minutes) | 95.2% (159/167) |
| Practical guides | 91.3% (84/92) |
| Marketing copy | **81.8%** (54/66) |
| Social posts | **77.0%** (47/61) |

English AI text, 533 passages: **98.1%**. Marketing and social posts are the
weak spots - the registers AI writes most naturally.

Works across three different model families (GPT-3.5 / Qwen-1.5B / Qwen3-VL-30B),
so it learned general AI-writing features rather than one model's fingerprint.

## ⚠️ Known Limitations

1. **Short text is weaker**: <50 chars carries too little signal — inherent ambiguity (information-theoretic ceiling)
2. **It recognizes *model fingerprints*, not an abstract "AI feel"**: very accurate on real model output (measured: Qwen-1.5B 100%, Qwen3-VL-30B 96%, GPT-3.5 99.6%), but it misses deliberately evasive text
3. **An informed user can evade it**: knowing how the detector works, you can avoid every AI language habit (no "firstly / moreover / in conclusion", short sentences, concrete facts) and it scores low. Measured: five evasive AI-written passages all came back Low (p=0.006-0.069). This is a shared boundary of every statistical-feature detector, not a defect specific to this project.
4. **New models require retraining**: AI models keep evolving; the detector must be retrained with fresh data
5. **Not equivalent to Turnitin**: an independent metric, cannot match any commercial detector's exact percentage
6. **Symbol/whitespace-only input is rejected** with `error: no_meaningful_content` instead of a guessed probability

---

> **On English false positives.** An earlier build scored 9% of genuine human
> English text as AI. Cause: the training set was 24:1 human:AI and the AI
> half skewed toward textbook exposition, so the model learned "clear structure
> = AI" rather than "AI diction = AI". Retrained with class_weight=balanced and
> recalibrated the output scale; false positives on 497 human answers went
> 45 -> 0, while AI recall held at 99%.

## 🤝 Technical Notes

### Why TF-IDF instead of Transformers?

Measured on CPU: roberta-base takes 33 s per training step (44 min for 80 steps) — completely impractical.
Switched to character-level TF-IDF + logistic regression: **trains in 68 s, with higher F1**.

### Why mix in Qwen-generated data?

HC3 is 2022 GPT-3.5 style — it performs poorly on modern model output (English only 0.05).
After mixing 1,860 modern Chinese + 888 modern English AI texts generated by local Qwen:
- Chinese modern-AI detection: 96.7%
- English fixed from 0.05 to **0.9905**
