# 本地训练日志 2026-11-20（纯本机算力）

这一天的训练只用了本机 CPU（Core Ultra 7 255H，16 线程）。
GPU 试过，结论在文末第 5 节 —— 对这个项目的模型没用。

写这份日志的目的是留下**没成的东西和为什么**。只记成功案例的日志，
会让后来的人以为这些指标很容易。

---

## 1. 英文模型：修掉「文档与产物不一致」

仓库里 `pred_en` 指向 `detector_en_v5`，而 README 写的指标来自另一次训练。
实测 v5 在 HC3 英文 AI 答案上**只检出 13.3%**（AI 侧均分 0.105）——
它训练时 AI 样本只有 1,702 条、人类 40,847 条，学成了「几乎全判人类」。

### 特征/超参搜索（48 组）

| 项 | 结果 |
|---|---|
| 最优向量化 | `char_wb(2,5)` + `word(1,2)` 双特征，516,770 维 |
| 最优 C | 30 |
| 分组独立集 11,160 条 | **F1 0.9905 / 误报 0.40% / 召回 98.92% / AUC 0.99979** |
| 产品级 600 条对照 | 旧 13.3% → 新 100% 检出，真人误报均 0% |

同时关掉一个隐患：英文那层 `0.25 → 0.5` 重标定是为 v8 的
`class_weight="balanced"` 写的。新模型没用 balanced 权重，再套这层
会把真人分数整体抬到 0.27 起，迟早翻过阈值。改成只对 `en_tier0` 生效。

## 2. 英文功能性文体：补数据，但只补到一半

v9 修好召回后，功能性文体仍然瞎：备忘 0.281 / 客服 0.056 / 纪要 0.399 / 指南 0.533。
根因是数据 —— 英语 AI 训练文本只有 1,927 条，人类 52,402 条，且几乎全是问答体。

用本机 llama.cpp + 本机 1.5B 权重生成了两批样本（约 10 条/分，全程本机）：

| 数据量 | 4 条探针 | **8 条未见样本** | 独立集 F1 | 误报 |
|---|---|---|---|---|
| 0 条（基线） | 0/4 | — | 0.9895 | 0.45% |
| 126 条（v10，已发布） | 2/4 | **3/8** | 0.9899 | 0.55% |
| 312 条 | 3/4 | **2/8** | 0.9889 | 0.68% |

**312 条那一版没发。** 它在 4 条探针上是 3/4（按门槛够格），
但 8 条从未进过训练集的样本上只有 2/8，比 126 条那版还差。
逐条看，8 条里 6 条分数上升，但 memo(0.069→0.056) 和
minutes(0.514→0.468) 恰好掉到线下，净值少一条。

结论：**生成数据越多，探针越容易被拟合。** 选模型必须有第二套留出样本。

## 3. 中文模型：完整搜索没能超过现有模型，不换

- 阶段1：80 个向量化配置 × 4 个 C × 2 种 class_weight，跑完 312 个模型
  - 单次切分最优 `score 0.9788`（char_wb(2,5), min_df=2, 30 万维, C=30）
  - 数据已经 1.01:1 平衡，`class_weight=None` 与 `balanced` 结果完全一致
- 阶段2：3 折 GroupKFold 细搜索，最优 `cv_score 0.9813`（char_wb(2,4), min_df=1, 20 万维, C=100），
  但**误报 1.45%**，且在诚实口径上没有超过现有 `detector_zh_final`

同时试过三种融合，全部更差：

| 方案 | F1 |
|---|---|
| 单 char_wb(2,5)（基线） | **0.9787** |
| char + word hstack | 0.9770 |
| NB-SVM（log-count ratio 加权） | 0.9700 |
| 概率平均 | 0.9658 |

**结论：中文模型不换。** 差异在噪声内，换只是拿风险换一个好看的数字。

## 4. tier3 CNN：训练了，但没能证明更好

| 版本 | 参数 | 自己的切分 | 共同样本 |
|---|---|---|---|
| 线上 detector_cnn_full | 0.47M | 0.9709 | **0.9975** |
| 重训（原配置） | 0.47M | 0.9703 | — |
| 加大版（128 维嵌入、8 层卷积、320 长度） | 1.10M | 0.9766 | 0.9962 |

加大版在自己切分上 +0.0057，但在共同样本上**输给**旧模型 0.0013。
两个数字来自不同切分，不能直接比 —— 而能比的那套说明它没有更好。
**因此不替换。**

顺手修了一个真 bug：加载器硬编码卷积核 `[2,3,4,5,6]` 和词表 `len(c2i)+1`，
任何换了核组合或词表偏移差一位的训练脚本，模型 `load_state_dict` 直接形状不匹配。
改成从 `state_dict` 读，已验证线上模型输出零偏差。

## 5. GPU：测过了，这个项目用不上

| 项 | 结果 |
|---|---|
| `torch` 版本 | 2.15.0+**cpu**，`torch.xpu.is_available()` = False |
| Windows 上的 XPU | 官方 PyTorch 不支持（只 Linux） |
| `torch-directml` | 装上后识别到 `Intel(R) Arc(TM) 140T GPU (16GB)` |
| DirectML 实际速度 | batch 64：CPU 290 样本/秒 vs **GPU 93 样本/秒（慢 3 倍）** |
| llama.cpp 构建 | 纯 CPU，日志只见 `n_threads`，无 GPU 后端 |

1.1M 参数的小卷积网络喂不饱 GPU，DirectML 的 kernel 启动开销压倒计算。
**结论：这类模型该在 CPU 上训。** 不要假设「有 GPU 就该用」，先测交叉点。

---

## 6. 教训

1. **两套评估集是硬要求。** 只有目标探针，会在拟合和泛化之间选错。
2. **跟别人的模型比分数，必须先证明那批文本谁都没训过。** 做不到就说无法比较。
3. **加载器不许硬编码结构。** 形状全从 `state_dict` 读，改完验证零偏差。
4. **换模型的证据清单**：独立集 F1 不降、误报不显著上升、未见样本方向一致、
   共同样本上直接对比。缺一条就不换，并把不换的理由写进 CHANGELOG。
5. **不要把语病当性能。** 早前报告的「0.804 → 0.244」是靠把公文改成病句换来的。
